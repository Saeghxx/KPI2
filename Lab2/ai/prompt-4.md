## 2. Діаграма Use Case у PlantUML

Скопіюй цей код у PlantUML. У діаграмі є люди, зовнішні системи, узагальнення акторів і Use Cases, а також зв’язки `include` та `extend`.

```

actor "Гість" as Guest
actor "Покупець" as Buyer
actor "Адміністратор" as Admin

Buyer --|> Guest

rectangle "Онлайн-книгарня" {

    usecase "Захищене зберігання\nпароля" as UC03

    usecase "Керування кошиком" as UC04
    usecase "Перевірити кошик" as UC05
    usecase "Оформити замовлення" as UC06
```

## 3. Пояснення зв’язків `include` та `extend`

| Зв’язок       | Тип       | Пояснення                                                                                       |
| ------------- | --------- | ----------------------------------------------------------------------------------------------- |
| UC-02 → UC-03 | `include` | Реєстрація обов’язково включає захищене зберігання пароля Customer.                             |
| UC-06 → UC-05 | `include` | Оформлення замовлення обов’язково включає перевірку кошика перед створенням CustomerOrder.      |
| UC-07 → UC-08 | `include` | Оплата замовлення включає перевірку результату, отриманого від платіжного шлюзу.                |
| UC-09 → UC-07 | `extend`  | Обробка відмови або таймауту розширює сценарій оплати лише тоді, коли виникає відповідна подія. |

Як читати стрілки:

- `A ..> B : <<include>>` — сценарій A обов’язково включає B; стрілка йде від базового сценарію до включеного.
- `A ..> B : <<extend>>` — сценарій A за певної умови розширює B; стрілка йде від розширення до базового сценарію.
- `Buyer --|> Guest` — Покупець успадковує можливості Гостя.
- `UC14 -|> UC13` та `UC15 -|> UC13` — створення й редагування книги є спеціалізаціями абстрактного Use Case «Керувати каталогом».

Примітка: UC-03 — внутрішня поведінка системи, а не окремий зовнішній актор. Платіжний шлюз і служба доставки — зовнішні системи. У цій діаграмі обробка відмови або таймауту оплати є умовним розширенням, тоді як перевірки кошика, результату платежу та захищене зберігання пароля є обов’язковими включеннями.
